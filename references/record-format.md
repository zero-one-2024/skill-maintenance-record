# 记录格式与输入

## 表格口径

正文只保留标题和表格。技能总览四列，每个技能一行；无仓库链接时写“未提供”，无分支信息时写“未核实”。“当前版本”可简记 `1.2.10；12机台已部署` 或 `代码1.2.10；部署1.2.9`，不能用最大版本号推导实际运行版本。

第二部分按技能分模块，每个正式版本一行，建议按发布日期从新到旧排列。同一版本多个工作环节合并概括，不复制完整报告。

| 列 | 填写内容 |
| --- | --- |
| 技能名称 | 与总览相同的名称；具体子能力在名称中注明，例如工序监测（扒渣链） |
| 修复日期 | 本次正式版本发布日期，`YYYY-MM-DD`；新建日期另在标题表达，不用它填补未知发布日期 |
| 问题版本 | 上一正式版本；首次发布写“初始版本”；不明写“未核实” |
| 问题描述 | 本轮主要问题或新增需求，最多概括几个关键点 |
| 原因分析 | 已确认原因；新功能写“新增能力”，未知写“未核实”，不猜测根因 |
| 解决方案 | 最终版本的主要变化，通常一至三项；不列中间候选和调试步骤 |
| 修复版本 | 本次正式版本号；新功能和初始发布也使用此列 |
| 验证结果 | 最终验证结论、少量必要指标和未覆盖范围；区分独立核验、报告结论与用户反馈 |
| 部署状态 | 实际环境/范围、发布与验收状态、重要未闭环事项；没有部署证据写“未核实” |
| 关联记录 | 可访问的发布、提交、MR 或验证报告链接；本地路径只作位置说明，不冒充在线附件 |

若技能没有可确认的正式版本迭代，在总览说明可确认状态；其维护表保留表头及一行“暂无已确认的正式版本记录”，不将候选变成正式记录。

## 本地 XML 渲染器

`scripts/render_record.py` 只渲染本地草稿，不执行飞书操作，不自动合并线上文档。输入必须已经完成事实核对和同版本归并。同一技能的重复正式版本会报错，以免静默漏掉内容。空白版本或过程记录不能作为正式发布录入；正式性依赖来源证据，脚本不以版本字符串判定。

在 `lark-doc` 返回的独占工作区内保存输入与输出：

```bash
python3 /实际技能目录/scripts/render_record.py \
  --input /独占工作区/record.json \
  --output /独占工作区/draft.xml
```

将 `/实际技能目录` 与路径替换成当前技能和 `init-draft` 的实际返回路径。不要复制到固定的跨任务草稿目录。

输入示例为虚构数据，仅用于说明字段：

```json
{
  "project_name": "示例项目",
  "created_date": "2026-11-12",
  "skills": [
    {
      "id": "inspection",
      "name": "巡检监测",
      "repository": "https://example.com/team/inspection",
      "current_version": "1.2.10；测试环境已部署",
      "branch": "main",
      "releases": [
        {
          "status": "released",
          "date": "2026-11-12",
          "previous_version": "1.2.9",
          "version": "1.2.10",
          "problem": "部分作业漏记。",
          "cause": "完成判断耦合。",
          "solution": "独立判断作业完成并优化调度。",
          "validation": "报告称回归通过；完整时段未验证。",
          "deployment": "测试环境已部署；生产未部署，业务验收未完成。",
          "references": [
            {"label": "发布报告", "url": "https://example.com/releases/1.2.10"}
          ]
        }
      ]
    }
  ]
}
```

- `project_name`、技能 `id/name/current_version` 及每条发布的 `status/version` 必填；`status` 必须为 `released`，候选或过程记录应先从输入中移除。
- `created_date` 使用 `YYYY-MM-DD`；首次创建省略时取当前北京时间，后续草稿必须传入原创建日期，不滚动到今天。
- `skills` 为非空数组。`releases` 可为空，日期和其他缺失事实会显示“未核实”或“未提供”，不自动补成成功。
- `repository` 可为 HTTP(S) 仓库链接或纯文本位置；`references` 是 `label/url` 数组，只接受 HTTP(S) 链接。秘密不得写入任何字段。
- 渲染器保持技能及发布输入顺序，不排序或推断“最新”，以免把版本号大小误当成部署状态。编辑已有文档时，输入需保留相关表的全部历史行；输出只用作局部补丁材料，不用于整篇覆盖。

开发验证：`python3 -m unittest discover -s tests -v`（在本技能目录运行）。
