# Skill Maintenance Records

[English](README.md) | [简体中文](README.zh-CN.md)

一个用于编制和更新项目技能维护记录的 Codex Skill，支持业务监测技能和 Codex Skill。默认保存到飞书，内容为技能最新状态总览与简洁的正式版本迭代记录，每个正式版本只保留一条记录。

## 使用条件与安装

- Codex 能读取相关项目材料和引用的聊天。
- 写入飞书需要已安装的 `lark-doc` 技能、`lark-cli`，以及具有目标文档创建或编辑权限的用户身份认证；本仓库不包含这些依赖。
- 可选的本地渲染器与测试需要 Python 3.9 及以上版本，以及 `Asia/Shanghai` 时区数据；只使用标准库，无需第三方 Python 包。

安装到默认的本地技能目录：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/zero-one-2024/skill-maintenance-record.git ~/.codex/skills/skill-maintenance-record
```

若配置了自定义 `CODEX_HOME`，使用其下的 `skills` 目录。已安装同名技能时更新现有安装；若现有安装通过符号链接指向开发工作区，保留该链接，无需再克隆一份。

## 调用方式

提供项目名称，以及关联聊天、发布报告或文件即可，无需手工准备 JSON。

首次编制：

```text
使用 $skill-maintenance-record，根据当前会话和附带的发布报告，
为示例项目编制技能维护记录，保存到飞书“我的文档库”。
只记录关键正式版本迭代。
```

更新已有记录：

```text
使用 $skill-maintenance-record，根据 <发布报告>，把巡检监测技能
1.2.10 的更新加入 <维护文档链接>，同步技能总览，保留其他技能
和历史版本，1.2.10 只保留一条简洁记录。
```

仅生成本地草稿：

```text
使用 $skill-maintenance-record，根据我提供的文件编制示例项目
技能维护记录，先生成本地草稿，不写入飞书。
```

明确调用技能编制记录，即可创建本次记录或更新指定记录。项目规则已有统一维护入口时继续维护该文档；没有既定入口时，默认在飞书**“我的文档库”**首次新建。再次调用或跨日不会自行另建文档；明确要求另建快照时按该要求执行。

## 维护记录命名与格式

新建文档命名：

```text
{项目名称}技能维护记录_{YYYYMMDD}
立中项目技能维护记录_20261112
```

日期取文档创建时的北京时间 `Asia/Shanghai`，不使用版本发布日期。项目名称沿用用户提供的名称，不再额外添加“项目”，也不限制为 15 字。更新旧记录时保留原创建日期和标题，明确要求改名时再改。

正文只有两个一级模块，标题以外的内容全部放入表格。以下 Markdown 表格用于展示格式；实际写入飞书时使用原生表格和自动编号标题。示例数据均为虚构。

### 1. 技能总览

每个技能一行，同步最新确认的版本和状态：

| 技能名称 | 仓库地址 | 当前版本 | 分支说明 |
| --- | --- | --- | --- |
| 巡检监测 | https://example.com/team/inspection | 1.2.10；测试环境已部署 | main |

代码版本与部署版本不一致时简短注明两者，不根据代码版本推断已经部署。

### 2. 技能维护记录

第二部分按技能设置独立子模块，每个技能各一张十列表格，每个正式版本一行：

| 技能名称 | 修复日期 | 问题版本 | 问题描述 | 原因分析 | 解决方案 | 修复版本 | 验证结果 | 部署状态 | 关联记录 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 巡检监测 | 2026-11-12 | 1.2.9 | 部分作业漏记。 | 完成判断耦合。 | 独立判断作业完成并优化调度。 | 1.2.10 | 报告称回归通过；完整时段未验证。 | 测试环境已部署；生产未部署，业务验收未完成。 | [发布报告](https://example.com/releases/1.2.10) |

修复日期记录正式版本发布日期；问题版本为上一正式版本，修复版本为本次正式版本。新功能在问题描述中写新增需求，原因分析可写“新增能力”；首次发布的问题版本写“初始版本”。缺少依据的事实写“未核实”或“未提供”。

“关键版本”不只指语义版本号中的大版本，`1.2.9 → 1.2.10` 也可以是关键正式迭代。同一技能、同一版本的工作归并为一条，补充验证时更新原行；不同正式版本分别保留。省略候选轮次、调试步骤、中间测试、完整源码与过程叙述，保留验证未覆盖、业务验收未通过等关键限制。

字段解释和虚构 JSON 示例见[记录格式与输入](references/record-format.md)。技能正文与该参考文件均采用中文。

## 可选的本地渲染器

助手可以将已核实、已归并的 JSON 转换为原生表格 XML。在仓库根目录执行，并将路径替换为实际输入、输出路径：

```bash
python3 scripts/render_record.py --input /absolute/path/record.json --output /absolute/path/draft.xml
```

创建飞书文档时，使用 `lark-doc` 工作流分配的独占草稿目录。渲染器保留输入顺序，拒绝同一技能的重复版本和非 `released` 状态记录；缺失事实按未知展示，不自动推断最新版本，也不判断发布证据是否真实。输入与输出不能为同一路径；有效渲染会写入指定路径，可能替换已有本地文件。

渲染器不执行飞书操作。更新已有文档时，通过编辑工作流局部修改，保留其他技能、历史版本、链接和资源，不用渲染器输出整篇覆盖线上文档。完成云端归档须实际写入并回读核对受影响的表格，仅本地解析通过不能视为完成。依赖、认证或权限不足时保留本地草稿并说明剩余工作。

## 测试

在仓库根目录执行：

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖命名、北京时间、表格结构、版本去重、候选记录拒绝、缺失事实、验证限制、XML 转义、命令行行为、README 链接及文档中的渲染命令。测试均在本地运行，不创建或修改飞书文档。
